# API-каталог Самарского университета

Исследование публичных и доступных по штатному входу API официальных сайтов Самарского университета. Цель — собрать проверяемый каталог HTTP-интерфейсов: адреса, методы, параметры, форматы ответа, требования к доступу и примеры.

## Текущее покрытие

| Система | Проверенное API | Статус |
| --- | --- | --- |
| `ssau.ru` | `GET /api/news/` — новости; `GET /rss/` — RSS; `POST /rasp/search` — публичный поиск групп | Все три маршрута проверены 2026-10-27; API новостей документировано |
| `ssau.ru/rasp` | Страницы расписания и поиска групп | Поиск `POST /rasp/search` подтверждён; отдельный API расписания не найден в захватах |
| `www.ssau.ru/staff` | API каталога сотрудников пока не найден | Страница и фильтр просмотрены; запрос к API не попал в кандидаты захвата |
| `lk.ssau.ru` | Login flow и авторизованный JSON API расписания замечены в клиенте | Параметры записаны; вход и запрос с действующей сессией не выполнялись |
| `priemsamara.ru` | `GET /get_program/{id}` и `GET /get_fac/{id}/bac` | AJAX-маршруты отдают публичные HTML-фрагменты; проверены при кликах в интерфейсе |
| `alumni.ssau.ru` | WordPress REST API `/wp-json/` | Индекс 185 маршрутов и публичная выдача записей проверены; полный список шаблонов без данных ответов сохранён в `data/alumni-wp-rest-routes.json` |
| `journals.ssau.ru` | OAI-PMH `/index/ru/oai` | `Identify`, `ListMetadataFormats` и `ListSets` проверены; доступны метаданные нескольких журналов |

Это начальный проверенный каталог, а не заявление о полном обнаружении всех интерфейсов. «Все API» — большая цель: у университета есть отдельные сайты и цифровые сервисы, у каждого из которых свой фронтенд и границы доступа. См. [план покрытия](docs/coverage.md).

## Первый найденный API

Официально опубликован API новостей: `GET https://ssau.ru/api/news/`. Он возвращает JSON, а при `xml=true` — XML (`text/xml` в проверенном ответе). Документированы поиск, выборка по ID, пагинация, даты, типы новостей, теги, язык и режим слайдшоу. Рядом работает RSS-лента `GET https://ssau.ru/rss/`, ссылка на которую размещена в подвале портала. Подробности — в [описании интерфейсов новостей](docs/apis/public-news.md).

В клиенте расписания найден и проверен `POST https://ssau.ru/rasp/search`: он ищет группы и возвращает JSON. Запрос требует CSRF-токен из страницы расписания; шаги и схема ответа записаны в [карточке поиска групп](docs/apis/schedule-search.md). В том же проекте замечен защищённый endpoint личного кабинета для расписания; он ещё не проверялся напрямую и отмечен как кандидат.

На связанном сайте выпускников обнаружен WordPress REST API: доступен индекс маршрутов и проверено чтение ограниченной публичной выборки записей. Электронные журналы предоставляют OAI-PMH для экспорта метаданных; подтверждены идентификация, форматы и наборы. Подробности: [API выпускников](docs/apis/alumni-wordpress.md) и [OAI-PMH журналов](docs/apis/journals-oai-pmh.md).

## Файлы каталога

- `data/api-inventory.json` — машиночитаемый список найденных сервисов и маршрутов.
- `openapi.yaml` — OpenAPI-описание подтверждённых публичных API и RSS-ленты.
- `data/alumni-wp-rest-routes.json` — сокращённый индекс маршрутов WordPress REST API сайта выпускников (пути, методы и имена аргументов; без публикаций и их содержимого).
- `docs/apis/` — человекочитаемые карточки API с источниками и результатами проверки.
- `api-anything/` — экспортируемые операции для [API Anything](https://github.com/goodnight000/api-anything). В каталог добавляются только проверенные публичные операции; рабочие сессии и куки сюда не записываются.
- `docs/coverage.md` — границы исследования, очередь систем и критерии полноты.

## Правила проверки

1. Сначала читаем официальную документацию и публичные страницы сайта.
2. Фиксируем только реально наблюдавшиеся запросы. HTML-страницы и файлы не называем API без подтверждения машинного интерфейса.
3. Для каждой операции сохраняем дату, источник, HTTP-метод, параметры, формат и пример результата.
4. Различаем статус «официально документировано», «обнаружено во фронтенде» и «проверено повторным запросом».
5. Не сохраняем пароли, токены, cookies и персональные ответы. Для авторизованных систем используются только аккаунты и данные с разрешённым доступом.
6. Не отправляем изменяющие запросы: каталог на первом этапе только для чтения.

## Проверенные примеры

См. карточку новостей. Из текущего окружения проверены JSON-ответы для списка, поиска и получения записи по ID, а также XML-ответ; подробные параметры сверены с официальным руководством университета.
