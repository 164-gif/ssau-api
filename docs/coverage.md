# План покрытия API

## Что значит «все API»

Абсолютно подтвердить отсутствие неописанных, закрытых или неиспользуемых API только по публичным страницам нельзя. В этом проекте полнота будет означать: систематически просмотрены публично доступные официальные веб-интерфейсы Самарского университета и связанные пользовательские системы; каждый реально наблюдавшийся HTTP-маршрут проверен отдельным запросом и записан с источником и границами доступа.

Поддомены и системы сначала фиксируются как **кандидаты**. Наличие сайта, HTML-страницы, JavaScript-файла или серверного маршрута само по себе ещё не подтверждает API.

## Системы-кандидаты

Список для проверки сформирован по ссылкам и разделам официального портала; он не утверждает, что все системы принадлежат одной команде или используют одну авторизацию.

| Система | Основание | Статус |
| --- | --- | --- |
| `ssau.ru` | Основной публичный портал, руководство API и расписание | Частично исследовано: API новостей подтверждён |
| `www.ssau.ru` | Канонический хост публичных страниц некоторых разделов | Частично исследовано: `/staff` проверен, запрос к API не попал в кандидаты захвата |
| `lk.ssau.ru` | Ссылка «Личный кабинет» на портале | Не исследовано; авторизованные операции изучать только в разрешённом аккаунте |
| `priem.ssau.ru` | Ссылка на сайт приёмной кампании | Не исследовано |
| `repo.ssau.ru` | Ссылка на репозиторий университета | Не исследовано |
| `mail.ssau.ru` | Ссылка на веб-интерфейс почты | Вне текущей публичной части; не исследовано |
| `ai.ssau.ru`, `engineering.ssau.ru`, `podcasts.ssau.ru` и другие официально связанные поддомены | Ссылки основного портала | Не исследовано; добавлять по мере подтверждения принадлежности и необходимости |

## Очередь работ

1. Проверить карты сайта, `robots.txt`, публичные страницы и официальные API-документы основного домена. `robots.txt` открыт и не содержит запретов; `/sitemap.xml` на момент проверки отвечает 404.
2. Для публичных интерактивных разделов выполнить ограниченные браузерные захваты запросов, исключая аналитику и сторонние ресурсы. Уже просмотрены главная, новости, расписание, страница расписания факультета и раздел сотрудников; отдельный first-party XHR/Fetch запрос не попал в кандидаты захватов API Anything.
3. Исследовать расписание: выяснить, откуда сайт берёт список групп/преподавателей и расписание; отличать публичный интерфейс от личного кабинета. Страница расписания факультета сейчас отдаёт HTML и ссылки на другие страницы расписания.
4. Отдельно описать приёмную кампанию, репозиторий и прочие системы, только если они в заявленном охвате.
5. Закрытые личные кабинеты оставить как отдельную область с явным требованием разрешённого тестового аккаунта; не сохранять cookies и персональные ответы.
6. Для каждого кандидата фиксировать результат: найдено, не найдено на проверенных страницах, недоступно, либо не исследовано. «Не найдено» не трактовать как доказательство отсутствия.

## Критерии подтверждённого API

- Зафиксированы метод, URL и тип контента из документации или запроса фронтенда.
- Запрос повторён отдельно с безопасными публичными параметрами.
- Записаны параметры, формат результата, требования к входу и дата проверки.
- Примеры не содержат персональных данных, секретов или живых сессионных значений.
- Запросы, меняющие данные, не запускаются без отдельного разрешения; каталог сейчас read-only.
